# Dokumen Spesifikasi Teknis (Specs) - Karsa Tiket

Dokumen ini merangkum seluruh arsitektur, batasan teknis, aturan data, dan spesifikasi fungsional untuk aplikasi **Karsa Tiket (Tiketing Event)** berdasarkan PRD dan Skema Firestore Tugas Mandiri Sesi 3.

---

## 1. Ringkasan Sistem & Tujuan
- **Nama Aplikasi**: Karsa Tiket
- **Konteks**: Layanan tiket komunitas kreatif untuk workshop & konser mini.
- **Tujuan**: Mengelola event, pembeli, tiket, pembayaran, kehadiran, dan rekap penjualan secara terintegrasi dengan validasi kuota otomatis.
- **Peran**: Single-role (Penyelenggara/Panitia disatukan untuk kebutuhan tugas mandiri CRUD).
- **Target Platform**: Web responsif (diutamakan mobile-first viewport).

---

## 2. Arsitektur Data & Skema Firestore

Aplikasi menggunakan 3 koleksi utama di Cloud Firestore. **Field dan nama koleksi tidak boleh ditambah atau diubah.**

### 2.1 Koleksi `event`
Menyimpan data master acara.
- **ID Dokumen**: Otomatis (Auto-generated by Firestore).
- **Struktur Field**:
  | Field | Tipe | Wajib | Aturan & Batasan |
  | :--- | :--- | :--- | :--- |
  | `nama` | string | Ya | 1 - 60 karakter |
  | `tanggal` | string | Ya | Format teks `YYYY-MM-DD` |
  | `lokasi` | string | Ya | 1 - 100 karakter |
  | `harga_tiket` | number | Ya | Bilangan bulat $\ge 0$ (0 = Gratis) |
  | `kuota` | number | Ya | Bilangan bulat 1 - 500 |
  | `tiket_terjual` | number | Ya | Bilangan bulat $\ge 0$, tidak boleh $> kuota$. Nilai awal = 0 |
  | `dibuat_pada` | timestamp | Ya | Server timestamp (`serverTimestamp()`) |

- **Field Turunan (Dihitung di UI)**:
  - `sisa_kuota` = `kuota - tiket_terjual`
  - Status `Habis` jika `sisa_kuota === 0`

---

### 2.2 Koleksi `pembeli`
Menyimpan data master kontak pembeli tiket.
- **ID Dokumen**: `no_whatsapp` (Nomor WhatsApp menjadi Document ID untuk mencegah duplikasi).
- **Struktur Field**:
  | Field | Tipe | Wajib | Aturan & Batasan |
  | :--- | :--- | :--- | :--- |
  | `nama` | string | Ya | 1 - 60 karakter |
  | `no_whatsapp` | string | Ya | Sama persis dengan Document ID. Diawali `08`, 10 - 13 digit angka |
  | `email` | string | Ya | Mengandung karakter `@`, maks. 80 karakter |
  | `dibuat_pada` | timestamp | Ya | Server timestamp (`serverTimestamp()`) |

---

### 2.3 Koleksi `tiket`
Menyimpan transaksi pembelian tiket event.
- **ID Dokumen**: Otomatis (Auto-generated by Firestore).
- **Struktur Field**:
  | Field | Tipe | Wajib | Aturan & Batasan |
  | :--- | :--- | :--- | :--- |
  | `event_id` | string | Ya | ID dokumen `event` terkait |
  | `nama_event` | string | Ya | Snapshot nama event saat transaksi dibuat |
  | `tanggal_event`| string | Ya | Snapshot tanggal event (`YYYY-MM-DD`) |
  | `pembeli_id` | string | Ya | ID dokumen `pembeli` (`no_whatsapp`) |
  | `nama_pembeli`| string | Ya | Snapshot nama pembeli saat transaksi dibuat |
  | `harga_tiket` | number | Ya | Snapshot harga satuan tiket event saat transaksi dibuat |
  | `jumlah_tiket`| number | Ya | Bilangan bulat 1 - 5, dan $\le sisa\_kuota$ |
  | `total` | number | Ya | `harga_tiket * jumlah_tiket` |
  | `status` | string | Ya | Status transaksi (lihat state machine) |
  | `dibuat_pada` | timestamp | Ya | Server timestamp (`serverTimestamp()`) |

---

## 3. Alur Status Transaksi (*State Machine*)

Tiket memiliki alur status yang ketat dan satu arah (tidak boleh melompat atau mundur):

```
       [ Tiket Dibuat ]
              │
              ▼
      ┌─────────────────┐
      │ menunggu_bayar  │ ◄── Status Awal
      └────────┬────────┘
               │
       ┌───────┴───────┐
       ▼               ▼
 ┌───────────┐   ┌────────────┐
 │   lunas   │   │ dibatalkan │ (Kuota event dikembalikan: tiket_terjual - jumlah_tiket)
 └─────┬─────┘   └────────────┘
       ▼
 ┌───────────┐
 │   hadir   │ (Check-in saat acara)
 └───────────┘
```

### Tabel Transisi Status:
| Status Asal | Boleh Berubah Ke | Efek terhadap Kuota Event | Keterangan |
| :--- | :--- | :--- | :--- |
| `menunggu_bayar` | `lunas` | Tetap | Bukti transfer terverifikasi |
| `menunggu_bayar` | `dibatalkan` | `tiket_terjual - jumlah_tiket` | Kuota event dikembalikan otomatis |
| `lunas` | `hadir` | Tetap | Peserta check-in di lokasi acara |
| `hadir` | *(Final)* | - | Tidak dapat diubah kembali |
| `dibatalkan` | *(Final)* | - | Tidak dapat diubah kembali |

---

## 4. Tiga Invariant (Aturan Integritas Data Wajib)

1. **Invariant 1 (Event)**: `harga_tiket >= 0` dan `tiket_terjual <= kuota`.
2. **Invariant 2 (Tiket)**: `1 <= jumlah_tiket <= 5` dan `jumlah_tiket <= sisa_kuota`.
3. **Invariant 3 (Total Tiket)**: `total === harga_tiket * jumlah_tiket`. Snapshot `harga_tiket` dan `nama_event` tidak boleh berubah jika data event master diubah di kemudian hari.

## 5. Spesifikasi Modul & Kebutuhan Fungsional

### 5.1 Modul Event
- **Fitur**:
  - Daftar Event: Kartu event menampilkan nama, tanggal, lokasi, harga (format Rupiah), sisa kuota, badge "Habis" jika kuota = 0.
  - Tambah & Edit Event: Form input nama, tanggal (`type="date"`), lokasi, harga, kuota.
  - Validasi Edit: Kuota tidak boleh diperkecil lebih rendah dari `tiket_terjual` saat ini.
  - Hapus Event: Dialog konfirmasi bahaya sebelum eksekusi `deleteDoc`.
- **Query**: `query(collection(db, "event"), orderBy("tanggal"), limit(20))`

### 5.2 Modul Pembeli
- **Fitur**:
  - Pencarian Realtime: Input cari berdasarkan nama atau nomor WhatsApp.
  - Tambah Pembeli: Pengecekan `getDoc` terlebih dahulu; jika ID dokumen (`no_whatsapp`) sudah ada, tolak dengan pesan `"Nomor WhatsApp sudah terdaftar"`.
  - Edit Pembeli: Ubah nama dan email.
  - Hapus Pembeli: Dialog konfirmasi sebelum hapus.
- **Query**: `query(collection(db, "pembeli"), orderBy("nama"), limit(20))`

### 5.3 Modul Tiket
- **Fitur**:
  - Tabs Filter: Semua, Menunggu Bayar, Lunas, Hadir, Dibatalkan.
  - Form Pembuatan Tiket:
    - Dropdown Event (hanya menampilkan event yang memiliki sisa kuota $> 0$).
    - Dropdown/Search Pembeli.
    - Input jumlah tiket (1 - 5, maks sisa kuota).
    - Kalkulasi total instan.
    - Saat submit: Buat dokumen tiket dengan `status: "menunggu_bayar"`, dan lakukan `increment(jumlah_tiket)` pada `event.tiket_terjual`.
  - Aksi Status:
    - Jika `menunggu_bayar`: Tombol "Tandai Lunas" dan "Batalkan".
    - Jika `lunas`: Tombol "Check-in (Hadir)".
- **Query**: `query(collection(db, "tiket"), orderBy("dibuat_pada", "desc"), limit(20))`

### 5.4 Modul Rekap
- **Fitur**:
  - Event Selector: Dropdown untuk memilih event aktif.
  - KPI Stat Cards:
    - Total Tiket Terjual
    - Sisa Kuota
    - Total Pendapatan: Hanya menghitung tiket dengan status `lunas` dan `hadir`.
    - Total Hadir: Jumlah pembeli yang telah check-in.
  - Progress Bar: Persentase kapasitas terisi (`(tiket_terjual / kuota) * 100%`).
- **Query**:
  - `getDoc(doc(db, "event", eventId))`
  - `query(collection(db, "tiket"), where("event_id", "==", eventId))`

## 6. Spesifikasi UI/UX & Standar 3-State

Setiap halaman list **wajib** mengimplementasikan 3 state:
1. **Loading State**: Skeleton loading atau spinner yang rapi saat mengambil data dari Firestore.
2. **Empty State**: Ilustrasi/ikon, pesan jelas (misal: "Belum ada event"), serta tombol aksi langsung (misal: "Tambah Event Baru").
3. **Error State**: Pesan kesalahan ramah pengguna disertai tombol **"Coba Lagi"** untuk *retry query*.

## 7. Spesifikasi Firestore Security Rules (`firestore.rules`)

Rules harus menolak seluruh masukan tidak sah berikut:
1. Dokumen `event`:
   - `nama` & `lokasi`: string tidak kosong, `nama.size() <= 60`, `lokasi.size() <= 100`.
   - `tanggal`: string dengan format `YYYY-MM-DD`.
   - `harga_tiket`: integer $\ge 0$.
   - `kuota`: integer antara 1 s.d. 500.
   - `tiket_terjual`: integer $\ge 0$ dan $\le kuota$.
2. Dokumen `pembeli`:
   - `nama`: string tidak kosong, `size() <= 60`.
   - `no_whatsapp`: diawali `'08'`, panjang 10 - 13 karakter, harus sama persis dengan `documentId`.
   - `email`: string mengandung `'@'`, `size() <= 80`.
3. Dokumen `tiket`:
   - `jumlah_tiket`: integer antara 1 s.d. 5.
   - `total`: harus persis `harga_tiket * jumlah_tiket`.
   - `status`: hanya boleh `'menunggu_bayar'`, `'lunas'`, `'hadir'`, atau `'dibatalkan'`.
   - Transisi status: Mematuhi aturan *state machine*.
